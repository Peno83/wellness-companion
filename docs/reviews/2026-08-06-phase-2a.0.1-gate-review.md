## 2. The red pipeline, precisely characterised

Run #5 (`d11cc18`) concluded **failure** with two red jobs. They are not the same kind of problem, and the distinction matters.

**`Spelling` — genuine content failure.** Check-run annotations:

> `6 spelling issues found in 2 of the 47 files checked.`
> `Unknown word (pwsh)` — `.github/workflows/documentation-quality.yml` lines 66, 69, 72, 75, 86
> `Unknown word (mongosh)` — `.github/scripts/Test-WorkflowPolicy.ps1` line 57

Confirmed against the config: `pwsh` and `mongosh` are **absent** from the 77-word dictionary, while `psql`, `vercel`, `flyctl` and `pipx` — their neighbours in the same policy rules — are present. Two words were missed.

**`Markdown lint` — transient infrastructure failure, not a repository defect.** Annotations:

> `Failed to resolve action download info`
> `Service Unavailable`

GitHub could not fetch the pinned action. No lint rule fired. The same lint configuration produced **success on run #4**, and locally produces 31 files / 0 issues. A re-run should clear it.

**Everything that enforces the phase boundary passed remotely:** `Phase boundary` ✅, `Secret patterns` ✅, `Broken links` ✅ — on both run #4 and run #5.

### Why local kept disagreeing with remote

The Phase 2A.0 finding was a **scope** mismatch. That is now genuinely fixed: `use_cspell_files: true` (verified as a declared input of the pinned `cspell-action` v7.2.1 via its `action.yaml`) makes the action honour the config's `files` list, and both sides now report exactly 47 files.

What remains is a **bundled-dictionary version difference**. I ran the corpus through `cspell@10` and `cspell@8` — both report 0 issues, because their bundled dictionaries know `pwsh` and `mongosh`. The cspell version bundled inside the pinned action does not. The same pattern explains the earlier markdownlint divergence: my local `markdownlint v0.41.1` has no MD060, while the pinned `markdownlint-cli2-action@v20` does.

This is the root cause behind three consecutive cycles of *"passes locally, fails remotely"*, and it is now the only thing standing between this repository and a green pipeline. See M-01.

## 3. Control independence — proven, not asserted

Phase 2A.0 M-02 said the workflow policy and the phase-boundary guard were sequentially dependent: the policy script validated one hardcoded path and relied on the boundary guard to block every other workflow filename.

I tested the fix adversarially. I built a directory containing **only** `documentation-quality.yml`, `Test-WorkflowPolicy.ps1` and the evil fixture, and verified that `Test-PhaseBoundary.ps1` was **absent** from that copy:

```text
phase-boundary script present in copy -> False

STEP 1  clean copy, WorkflowPolicy alone      → exit 0
        "independently enumerated .github/workflows and passed"

STEP 2  evil-build.yml planted, WorkflowPolicy alone → exit 1
        .github/workflows/evil-build.yml: workflow path is not approved
        .github/workflows/evil-build.yml: application builds are prohibited
        .github/workflows/evil-build.yml: arbitrary network commands are prohibited
        .github/workflows/evil-build.yml: package installation is prohibited
        .github/workflows/evil-build.yml: workflow_dispatch inputs are prohibited
        .github/workflows/evil-build.yml: write permissions are prohibited
```

The policy control discovered and rejected the unapproved workflow with the other control physically removed. Independently, the boundary guard rejects `.github/workflows/evil-build.yml` by exact-path match. **Two genuinely independent controls, each sufficient alone.** Check 10 and 11 satisfied by execution.

## 8. Decision

### CONDITIONAL APPROVAL FOR PHASE 2A FOUNDATION BUILD

No Critical findings. Every structural control I was asked to verify is working, and I verified the important ones by execution rather than inspection:

- The two workflow controls are **genuinely independent** — proven by rejecting a planted `evil-build.yml` with the other control physically deleted from the tree.
- The CSpell scope mismatch is **actually fixed**, not asserted: 47 files locally, 47 files in the remote annotation.
- The ADR collision is resolved with **neither decision lost**, and the AI-isolation decision correctly kept its identifier.
- All 15 dictionary additions are legitimate technical identifiers; **no genuine misspelling was suppressed**.
- Phase boundary, secret scanning and link checking pass **locally and remotely**.
- The repository contains no application source, manifest, database configuration, API, integration, scoring or health logic.
- And the register held the line: `P1.2-H-01` open, `P1.4-M-02` reopened unprompted, both citing the failing run.

The single outstanding item is that check 1 — a green run on `main` — is not met, because of two missing dictionary words and one unrelated GitHub outage. Approving outright would mean waiving the exact gate condition this project has now twice corrected itself for observing. It has earned better than that.

### Condition — one item

1. **Add `pwsh` and `mongosh` to `.cspell.json`, push, and confirm a green `Documentation quality` run on `main`.** Then record the run URL, commit SHA and conclusion in `GOV-FIND-001` and close `P1.2-H-01` and `P1.4-M-02`. If `Markdown lint` is still red, re-run it first to clear the transient failure. *(H-01, M-03)*

On that evidence this becomes **APPROVED FOR PHASE 2A FOUNDATION BUILD** with no further review required from me.

### Recommended as early foundation-build commits, not gating

Pin local tooling to the versions the workflow pins, or stop treating local runs as evidence (M-01) · add path-scoped `overrides` to the dictionary (M-02) · land the Dependabot upgrades once CI is green, which also addresses the Node 20 deprecation (M-04) · tag `governance-v1.1.1` (M-05) · confirm branch protection and route the first foundation change through a pull request so the governance checklist is exercised once (M-06).
