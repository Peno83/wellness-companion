## 3. What was verified working

This phase produced real, working engineering. Stated precisely because most of it is correct.

**The phase-boundary guard functions.** Executed against 20 crafted paths, it blocked every prohibited category — including `scripts/deploy.sh`, `requirements.txt`, `Cargo.toml`, `go.mod`, `Gemfile` and `lib/server.go`, none of which appear in its deny list. That is deny-by-default working as intended, which is the correct design and the right constitutional posture. Case variants (`SRC/Index.TS`) are caught. The self-test runs in CI *before* enforcement, so a broken rule set fails loudly rather than silently permitting.

**Action pinning is genuine.** I resolved all four SHAs against their upstream repositories. Every one corresponds to a real tag matching its version comment. This is the check that pinning usually fails — a plausible-looking but unverifiable hex string — and it passed.

**The amendment chain is properly constructed.** Constitution 1.1.0 supersedes 1.0.0 with a separate amendment record carrying every field the Constitution's own Governance Versioning clause names except the digest, correctly classified Minor, with compatibility and migration statements. The Registry's historical rows were **restored**, not rewritten: "Andrew Penfold" survives on all three original approval rows with correction notes, and the amendment states explicitly that the correction "does not transfer authority to a different person." This is exactly the right remediation of my Phase 1.3 C-01, and it is better than simply reverting would have been.

**Traceability is now real.** Sixty-three findings registered with decision, rationale, owner, target phase, status and evidence. `P1.2-H-01` was reopened rather than defended. `P1.1-H-13` — the safety-interruption explainability gap — is registered and owned.

**Least privilege is correct.** Read-only workflow token, `pull_request` rather than `pull_request_target`, per-job timeouts, concurrency cancellation, Dependabot scoped to actions only.

## 4. Findings

### Critical

**C-01 — Phases 1.3 and 1.4 remain entirely uncommitted; no tags, placeholder identity, no signing.**

`git log` shows two commits, both dated 2026-08-05, both from Phase 1.2. Everything reviewed here — Constitution 1.1.0, the amendment record, Registry 1.1.0, the AI Use Policy, both registers, the workflow, both guard scripts and all four tool configs — exists only as 15 modified and 12 untracked working-tree entries. `user.name` is still `Your Name`. `commit.gpgsign` is unset and both existing commits show `%G? = N`. No tags exist; `governance-v1.1.0` is proposed in the register but not created. Nothing has been pushed since `cb9e667`.

**In fairness, this is the AI Use Policy working as designed.** `GOV-AI-001` prohibits the Implementation Authority from executing "release, or production actions without specific human authorization," and the register records `P1.3-C-02` as Open with evidence "Requires user-authorized commit and push." The implementer correctly declined to act. That is the right behaviour and I credit it.

It remains gate-blocking nonetheless. Two consecutive phases of ratified governance sit outside the immutable record, with no digest, no attribution, no timestamp and no remote copy. Under the Constitution's own rule that *"absence of compliance evidence is treated as non-compliance,"* Constitution 1.1.0 is not yet evidence of anything. The action required is a human one and takes minutes.

### High

**H-01 — The workflow runs but cannot pass. Two of five jobs fail, and the register's evidence field is inaccurate.**

Measured by execution against the repository's own configs:

| Job | Result |
| --- | --- |
| `markdown-lint` | **FAIL** — 552 errors |
| `spelling` | **FAIL** — 235 issues across 26 of 28 files |
| `broken-links` | Not runnable locally; 181/181 relative links and anchors resolve under an independent checker, so this job should pass |
| `phase-boundary` | **PASS** — self-test passed, enforcement passed on 42 files |
| `secret-patterns` | **PASS** — passed on 42 files |

The markdownlint failures break down as 538 × MD060 (table-column-style), 11 × MD029, 2 × MD032, 1 × MD040. MD060 is a recent rule and is present in the pinned `v20`; but the remaining **14 errors come from MD029, MD032 and MD040, which exist in every markdownlint version**, so the job fails regardless of tool version. Those 14 are all in `docs/reviews/2026-08-05-phase-1-independent-architecture-review.md` — my own document, which was not considered when the config was tuned. The fix is mine to enable, not a defect in the config author's work.

The spelling failure is a configuration mismatch: `.cspell.json` declares `"language": "en-GB"` while the corpus is written in US English, so `behavior`, `normalize` and similar are flagged as unknown throughout. The 15-word dictionary omits roughly 220 required terms including `explainability`, `missingness`, `Criticals` — and `Penfold`, which the governance deliberately preserves in historical records.

Separately, `P1.2-H-01`'s evidence field reads *"Local checks pass; no GitHub Actions run exists yet."* The first clause is not correct. The finding's **Open** status is right; the evidence supporting it is not.

A permanently red pipeline is worse than none: it trains reviewers to ignore the signal, and the two jobs that genuinely enforce the phase boundary would then fail unnoticed inside the noise.

**H-02 — The phase-boundary guard unconditionally permits any new workflow file.**

`Test-PermittedPath` allows `^\.github/workflows/[^/]+\.ya?ml$` without qualification. Verified by probe: `.github/workflows/evil-build.yml` returns **ALLOW**.

Workflow files are executable. A new workflow can install packages, run a build, generate application source at runtime, or reach the network — none of which the file-based guard would observe, because the artifacts never land in the tree. The control whose entire purpose is preventing application development from entering a documentation-only phase has an executable path straight through it, and Phase 2A is precisely when new workflows start being added.

*Fix:* allowlist workflow files by name, or add a job that fails when a workflow file is added or modified without a corresponding governance reference in the PR body.

**H-03 — Two findings the project itself targeted at "Before Phase 2A" are still Open.**

- `P1.2-H-02` — metadata incomplete and status vocabulary conflicts. Verified still true: no artifact carries a content digest, which the Constitution's Governance Versioning clause requires by name; and every document uses `Status: Ratified` while `ARCH-VER-001` — itself bumped to 1.1.0 in this phase — still defines the permitted values as `draft｜approved｜active｜retired｜revoked`. The framework was revised without correcting the vocabulary it is being violated by.
- `P1.2-H-03` — ratified documents depend on unratified ones. Verified still true: `product-requirements.md`, `data-model.md`, `scoring-methodology.md`, `architecture-decisions.md`, `implementation-roadmap.md` and both package READMEs carry no metadata block at all, while `system-architecture.md` 1.0.1 and `security-design.md` 1.0.1 depend on them.

Both are honestly tracked. Both carry the project's own gate label. Neither is closed.

## 6. Decision

### CONDITIONAL APPROVAL FOR PHASE 2A

The Phase 1.4 work is substantively good and, unusually, verifiable. Every claim I could test by execution about the *governance chain* and the *guards* held up: the amendment is properly constructed, historical identity is preserved rather than rewritten, traceability is real, the boundary guard blocks 13 of 13 prohibited categories including unlisted ones, the secret scanner runs and fails closed, all four action SHAs resolve to genuine upstream tags, permissions are least-privilege, and no application code, package, database, API or integration has entered the repository.

Two things prevent unconditional approval. The governance layer is not in version control, so nothing here is yet durable evidence. And the quality half of the pipeline cannot pass, which — if left — will normalise a red CI at exactly the moment the boundary guard becomes the thing standing between a documentation repository and an application.

Neither is a design defect. Both are finishing work.

### Conditions before Phase 2A work begins

1. **Commit the record.** Set `user.name` to the accountable human, enable commit signing, commit and push Phases 1.3 and 1.4, and create the `governance-v1.1.0` tag. Then close `P1.3-C-02`, `P1.2-M-01`, `M-02`, `M-03` and `M-04`. *(C-01)*
2. **Make the pipeline green.** Fix the 14 version-independent markdownlint errors (or scope the config to exclude review documents); set cspell to `en-US` and extend the dictionary — including `Penfold`, which governance requires to remain. Run the workflow remotely, then close `P1.2-H-01` on that evidence. Correct its evidence field now, since "Local checks pass" is not accurate. *(H-01)*
3. **Close the workflow bypass** in the phase-boundary guard, and extend the self-test to cover it. *(H-02, L-04)*
4. **Close or explicitly re-target `P1.2-H-02` and `P1.2-H-03`** — both carry the project's own "Before Phase 2A" label. Adding a content digest and reconciling the status vocabulary in `ARCH-VER-001` are small changes; deciding the fate of the seven unversioned documents is a governance judgement. *(H-03)*

Items 1 and 2 are prerequisites. Items 3 and 4 may be the first commits *of* Phase 2A provided they land before any other Phase 2A change.

**Recommended, not gating:** add the missing secret patterns and a self-test for `Test-SecretPatterns.ps1`; enable GitHub secret scanning with push protection; fix the Registry effective-date inconsistency; register the Phase 1.3 Medium and Low findings; reorder the schema/migrations deny rule below the `.md` allow rule.
