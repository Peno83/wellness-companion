## 3. What I tried to break, and what held

Every adversarial probe below was executed, not reasoned about.

**Held — synthetic-only enforcement.** 17 of 17 prohibited paths blocked: `connectors/whoop/oauth.ts`, `garmin-api.ts`, `hume-api-client.ts`, `fitbit-api.ts`, `oura-api.ts`, `apple/healthkit.ts`, `health-connect-client.ts`, `samsung-health-sdk.ts`, `connectors/oura.ts`, `connectors/real/whoop.ts`, `connectors/synthetic/oauth-helper.ts`, `tests/fixtures/personal/…`, `tests/test-data/production/…`, `.env`, `.env.local`, `credentials.json`, `secrets/api.pem`. All 6 legitimate paths allowed, including a new `SyntheticOuraConnector.ts`. The negative-lookahead rule on `src/modules/connectors/` is well constructed.

**Held — governance fail-closed.** `requireGovernanceResult(undefined)` throws `GOVERNANCE_MISSING`; a `deny` result throws `GOVERNANCE_DENIED`; `SyntheticOnlyGovernanceEngine` denies any non-synthetic context.

**Held — feature-flag protection.** Governance, consent, provenance, audit and output validation are absent from `featureFlagKeys` entirely, so no flag can address them. All 16 flags default `false`, and `defaultFeatureFlags` survives an attempted mutation.

**Held — connector network prohibition.** With `globalThis.fetch` and `XMLHttpRequest` replaced by spies, all three connectors completed a sync and neither spy was called.

**Held — provenance.** Hume transported via Apple Health retains Hume as originating vendor with Apple Health as transport, and the two fields are never conflated.

**Held — determinism.** Six permutations of the candidate list produced one distinct result. The comparator is a total order: original-before-transported, then coverage descending, then identifier — with no vendor term anywhere in the function.

**Held — duplicate reconciliation.** The transported duplicate is marked ineligible with reason `"transported duplicate of original source"` while all three candidates remain in the returned evaluations. Nothing is deleted.

**Broke — module boundaries.** See C-02.

**Broke — secret handling.** See H-02.

## 4. Findings

### Critical

**C-01 — Phase 2A.1 is not committed; it exists only as a git stash.**

Detailed in §1. No commit, no attribution, no CI execution, no remote copy, and no gate can attach to it. The Constitution's release principles require traceability and evidence; a stash provides neither. This is recoverable in minutes and the work itself is not at fault, but it is disqualifying for a gate decision.

**C-02 — The module-boundary rules are advisory. Violations pass CI.**

`.dependency-cruiser.cjs` defines six rules. Only `no-circular` carries `severity: "error"`. The other five omit `severity` and therefore default to `warn`, and `depcruise` exits 0 on warnings.

I planted three violations — `src/modules/ai` → `src/lib/prisma`, `src/modules/source-selection` → `src/modules/ai`, `src/modules/governance` → `src/modules/feature-flags` — and ran the project's own architecture command:

```text
warn source-selection-cannot-use-ai: src/modules/source-selection/engine.ts → src/modules/ai/index.ts
warn governance-cannot-depend-on-feature-flags: src/modules/governance/index.ts → src/modules/feature-flags/index.ts
warn ai-cannot-access-persistence: src/modules/ai/index.ts → src/lib/prisma.ts

x 3 dependency violations (0 errors, 3 warnings). 39 modules, 20 dependencies cruised.

arch exit=0
```

`npm run validate` and the CI `platform-foundation` job both chain `test:architecture`, so **both would go green with the AI-to-persistence boundary breached.**

The affected rules are `ai-cannot-access-persistence`, `connectors-must-not-access-persistence`, `ui-cannot-access-persistence`, `source-selection-cannot-use-ai`, and `governance-cannot-depend-on-feature-flags` — precisely checks 8, 25 and 26, and the structural half of check 10. ADR-013 and the Constitution's AI Behaviour Rules make AI isolation the most emphasised control in the entire package, and Governance Enforcement Rule 1 requires that governance be _impossible to bypass by architecture_. A rule that reports and exits 0 is a bypass.

The fix is one line per rule, and I verified it works. With `severity: "error"` on the same rule and the same planted violation:

```text
error ai-cannot-access-persistence: src/modules/ai/index.ts → src/lib/prisma.ts
x 1 dependency violations (1 errors, 0 warnings).
exit=1
```

This must land before the code is committed, not after. Once merged, a green pipeline would assert boundaries it is not checking.

### High

**H-01 — Remote CI is red on HEAD.**

Run #7 on `42afad4` failed: _"1 spelling issue found in 1 of the 56 files checked"_ — `retryable` at `docs/architecture/capability-coverage-model.md:24`. `P1.2-H-01` was closed yesterday on run #6 and regressed on the very next commit, which was pushed to `main` red. A fix was being applied to `.cspell.json` concurrently with this review, so this is likely already closing — but the pattern is worth naming: closure evidence is per-commit, and nothing currently prevents a red commit reaching `main`. Branch protection with the workflow as a required check would.

**H-02 — Secrets leak through the logger in two of three paths.**

`src/lib/logger.ts` redacts context values whose **key** matches `/secret|token|password|credential|health|payload|measurement|user/i`. Executed probe:

| Path                                                             | Result                                         |
| ---------------------------------------------------------------- | ---------------------------------------------- |
| `log("info", "safe", { password: "…" })`                         | **redacted** ✅                                |
| `log("info", "safe", { dsn: "postgresql://u:<redacted>@h/db" })` | **logged verbatim in the reviewed version** ❌ |
| `log("info", "connecting to postgresql://u:<redacted>@h/db")`    | **logged verbatim in the reviewed version** ❌ |

The `message` parameter is never inspected, and key-name matching misses any container the author did not anticipate — `dsn`, `url`, `conn`, `uri`, `dbUrl`. `DATABASE_URL` carries credentials in every real deployment, and NFR-04 and the Constitution both prohibit sensitive content in logs. Value-level pattern redaction (the secret-scanner regexes already exist and could be reused) plus message scrubbing would close it.

## 5. What is genuinely good

Stated because most of this is strong, and because the two failures are narrow.

The **synthetic-only boundary** is the best control in the repository. The negative-lookahead on `src/modules/connectors/` combined with vendor-token filename matching blocked every one of seventeen attack paths I could construct, including `connectors/synthetic/oauth-helper.ts` — a path that looks legitimate and is not.

**Type-level guarantees are used well.** `synthetic: true` and `networkCalls: 0` as literal types, `Object.freeze` on default flags, branded `MetricIdentifier`, and `readonly` throughout. `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` are both on, which is rarer than `strict` alone and materially harder to satisfy — and `tsc` is clean.

**Source selection is the part I most expected to find problems in, and it is right.** Vendor-neutral by construction, deterministic under permutation, transported duplicates excluded without deletion, methodology breaks emitted only on genuine change, and origin never conflated with transport. The Hume-via-Apple case works exactly as the standard requires.

**The CI job added for this phase is comprehensive** — `npm ci`, audit, prisma generate, lint, format, typecheck, unit, architecture, build, Playwright — and the workflow-policy allowlist was extended with the exact new actions and commands rather than loosened. The two content rules that had to be relaxed (package install, build) were replaced by exact-match allowlisting, which is stronger than what it replaced.

## 7. Decision

## Decision: REJECTED FOR PHASE 2A.2

This is not a judgement on the quality of the work. Twenty-eight of thirty-five checks pass under execution, every adversarial probe against synthetic-only enforcement, provenance, determinism, duplicate handling, governance fail-closed, flag protection and connector network prohibition held, and the build, typecheck, lint, format, unit and e2e suites are all green. On the evidence I gathered, this is competent foundation code.

It is rejected for three specific reasons:

1. **The phase is not delivered.** HEAD contains no application code. The implementation is a stash, unattributed, with no CI ever executed against it and no remote copy.
2. **The AI-isolation boundary is proven non-enforcing.** Three planted violations produced warnings and a zero exit. This must be corrected _before_ the code lands, because after it lands a green pipeline will assert a boundary it is not checking.
3. **CI is red on `main`.**

None of these is deep. All three are hours of work, and one of them was already being fixed while I reviewed.

### Path to approval

1. Add `severity: "error"` to all five non-circular rules in `.dependency-cruiser.cjs`, and add a committed test or CI step that plants a violation and asserts a non-zero exit — so the enforcement itself is tested, not just the boundary. _(C-02)_
2. Redact by value as well as by key, and scrub the `message` parameter, in `src/lib/logger.ts`. Reuse the existing secret-scanner patterns. Add the three probe cases as committed tests. _(H-02)_
3. Land the `retryable` fix and confirm a green run on `main`. Enable branch protection with `Documentation quality` as a required check so a red commit cannot reach `main` again. _(H-01)_
4. Commit and push Phase 2A.1 with the above included, then re-run this gate against the committed tree. _(C-01)_
5. Replace the frozen timestamp constants with an injected clock before re-review. _(M-01)_

The remaining Medium and Low findings can be scheduled into Phase 2A.2 provided M-02, M-06 and M-01 are registered as personal-data blockers.

I would expect this to return as an approval. The controls that are hard to build are already working; what is missing is that two of them are not switched on, and the code is not yet in the repository.
