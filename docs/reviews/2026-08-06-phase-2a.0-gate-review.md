## 4. Content digest — the right answer

`ARCH-VER-001` 1.2.0 adds a *Content-digest canonicalisation milestone*:

> No governed artifact may claim a content digest until a canonicalisation method defines encoding, line endings, metadata inclusion, Unicode normalisation, trailing whitespace, final newline handling, and the digest algorithm. Hashing an editor-dependent file representation would not be reproducible evidence.

Targeted to **Phase 2A.1, before the first executable governance-policy bundle**. Until then each artifact records its immutable Git commit and release tag "as available provenance without mislabelling either as the required canonical content digest."

This is correct on the technical merits — a naive file hash across a repository with `.gitattributes` line-ending normalisation is not reproducible evidence — and it is correct on the governance merits, because it declines to fake compliance. The milestone is concrete and it lands at the same point as the Constitution's "signed policy bundles" obligation. Accepted as a proper re-targeting.

Run #4 on `8698f6b` (current HEAD): `Phase boundary` ✅, `Broken links` ✅, `Markdown lint` ✅, `Secret patterns` ✅, **`Spelling` ❌**.

`cspell-action` v7 with `incremental_files_only: false` does not restrict itself to the `files: "**/*.md"` input the way the local CLI glob does. This is the same class of defect as the previous cycle — **local pass was taken as evidence of remote pass, and the two invocations differ** — and it is why requiring a run URL rather than a local transcript was the right call.

Two consequences beyond the red badge: both Dependabot PRs (`markdownlint-cli2-action` → v24.2.0, `cspell-action` → v8.4.0) fail the same check, so the action-update mechanism cannot land its first updates; and a persistently red pipeline erodes the signal from the four jobs that do enforce the phase boundary.

*Fix:* add the 13 words to `.cspell.json`, or add `ignorePaths` entries for non-Markdown, then confirm green remotely.

**H-02 — `P1.4-M-02` is marked Closed on local-only evidence while the remote job it describes fails.**

The row reads `Closed`, evidence *"CSpell 10.0.1 checks 29 Markdown files…"*. The remote `Spelling` job is failing on the commit that contains this row. `GOV-FIND-001`'s own rule states *"`Closed` requires linked evidence and human confirmation."* A local transcript for a check that fails in CI is not confirmation.

The gate itself is not bypassed — `P1.2-H-01`, the umbrella "CI must pass remotely" finding, is correctly held **Open** with a `*` placeholder awaiting the run URL, which is exactly the discipline I asked for and it held. But `P1.4-M-02` should follow the same standard as its parent. Also note the file count discrepancy: the evidence says 29 Markdown files; the repository tracks 30.
